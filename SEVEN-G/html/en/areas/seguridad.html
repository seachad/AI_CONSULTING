AI action areas

Security and agents

How AI is protected, what an agent may do and with which suppliers.

In brief

What this area is about

AI security protects the model, the data and what an agent may do. The more autonomy an agent has, the more controls it needs: its own identity, least privilege, action limits and a kill switch. Suppliers are assessed and contracted with specific clauses.

Concepts

The concepts you need

Definitions taken from the SEVEN-G glossary (document 02). The codes are links to where each one is explained.

Agent
AI system that executes actions on other systems, data or people, or prepares them for human validation, by means of tools and permissions (autonomy A1, A2 or A3). A build tool capable of acting on repositories, environments or systems is also an agent.
Autonomy level
Degree to which a system acts without prior human validation of each action, on four levels A0–A3 (section 4.11). The level assigned is the highest of the actions the system can execute, not that of its usual use.
Prompt injection
Attack that introduces instructions to alter the intended behaviour of a generative AI system or an agent. It is direct when the user introduces it and indirect when it is hidden in content the system reads (documents, emails, websites, tool responses). Its controls must be checked with adversarial testing.
Corporate AI gateway
Common control point, outside the model, through which all traffic to models passes: input, output and context filters, leakage prevention, quotas, approved models, logging with a correlation identifier and, for agents, the intent decision point, with the same measured configuration for every initiative (SEG-26). It fails closed for sensitive actions and degraded for queries.
Corporate agent test bench
Versioned library of adversarial scenarios, derived from the threat model and from the company's own incidents, that tests agents and assistants through all their channels, tools and connectors with simulated users, built into the deployment pipeline: at A2 and A3 it runs at every deployment and a successful critical scenario blocks deployment; at A0 and A1, before G5 and after relevant changes (SEG-27).
Kill switch
Mechanism to stop an entire agent or a specific capability immediately without deploying code. When activated, it revokes credentials, blocks new actions, preserves logs and activates the fallback process. It is tested before G5 and periodically.
Least privilege
Principle whereby an agent only has a closed list of the tools, operations and data it needs, with read and write access authorised separately.
AI supplier (third party)
Third party that supplies models, platforms, software with AI features or services that use them, managed with requirement levels N1–N3.
