# Copilot Instructions for API_ROBOT_Flask_Dashboards

## Project Architecture Overview
- **Hybrid API/Dashboard System**: Flask-based multi-tenant dashboard platform with integrated API_ROBOT task processing engine
- **Key Components**: [flask_dashboards.py](flask_dashboards.py) (web app), [apirobot.py](apirobot.py) (task processor), [apirobot_external_integration.py](apirobot_external_integration.py) (bridge module)
- **Deployment Model**: Production uses PostgreSQL with Hypercorn/HAProxy for concurrency, development uses `.bat` database creation scripts
- **Multi-tenant SSO**: Microsoft Azure SSO with role-based authentication logic and tenant-specific configurations
- **Massive Monolith**: [app/__init__.py](app/__init__.py) contains 37K+ lines and is the main application factory - expect complex initialization patterns

## Critical Environment Configuration
- **Dynamic Environment Loading**: Uses `CM_DOTENV_SUFFIX` to load environment-specific `.env` files (default: `.env-seachad-minimum`)
- **Production Overrides**: `configuration/production_overrides.py` applies environment-specific settings from `production_env_overrides.json`
- **Database Configuration**: PostgreSQL with optional pgbouncer (port 6432), controlled via `CM_PGBOUNCER_ACTIVE` environment variable
- **Configuration Discovery**: [config.py](config.py) contains `config_dict` mapping deploy modes to configuration classes
- **Global Access Pattern**: Global `access` dict in `builtins` provides configuration to all modules via [apirobot_external_integration.py](apirobot_external_integration.py)

## Key Development Workflows
- **Environment Setup**: 
  ```bash
  pip install -e git+https://github.com/Seachad-TEAM/API_ROBOT.git@main#egg=apirobot_libraries&subdirectory=src/apirobot-libraries
  pip install -r requirements_SSO_python_3_13.txt  # or requirements_SSO_python_3_14.txt
  ```
- **Database Creation**: Run `create_databases_DevelopmentConfig.bat` (or ProductionConfig/TestConfig variants)  
- **Development Server**: Use [flask_dashboards_SSO.py](flask_dashboards_SSO.py) entry point for SSO debugging
- **Multi-Process Execution**: [apirobot.py](apirobot.py) supports `-m /K|/C` multiprocessing flags for task execution
- **Server Trace Debugging**: Controlled via `CM_LOG_DEBUG_SERVER_TRACE_LOG_ENABLED` environment variable
- **SQL Parsing Performance**: Uses [app/sql_parsing_optimizer.py](app/sql_parsing_optimizer.py) with configurable libraries (`CM_SQL_PARSING_LIBRARY`, `CM_CACHE_SQL_PARSING_ENABLED`)

## Authentication & Security Patterns
- **Role-Based SSO Logic**: Users with `HDN_` or `OFS_` email prefixes bypass SSO; admin roles (`admin`, `admin_secondary`) show password fields
- **Tenant Resolution**: Multi-tenant login via `ABMC_Tenant` table; single tenant auto-selects
- **Session Management**: Integrates with API_ROBOT session creation (`-s True` flag) for MongoDB audits and process control
- **Access Dictionary**: Global `access` dict in `builtins` provides configuration to all modules via `apirobot_external_integration.py`

## Integration Architecture
- **External Library Bridge**: `apirobot_external_integration.py` constructs global `access` configuration from multiple sources (.env, apirobot.json, system registry)
- **API_ROBOT Integration**: Task processing engine with JSON-based process definitions, supports audit trails and MongoDB connectivity
- **Cache Layer**: Redis integration via `apirobot_libraries.cache_REDIS` with qualified cache keys
- **Notifications System**: Three modes - SSE (real-time), POOLING (10s intervals), NEW_PAGE (on reload), controlled by `CM_NOTIFICATIONS_ENABLED`

## Monitoring & Observability
- **OpenTelemetry**: Full instrumentation in `app/telemetry.py` with buffered span export and admin panel integration
- **Prometheus Metrics**: Configured for Grafana dashboards (see README for setup instructions)
- **Concurrency Monitoring**: `app/concurrency_usage_logger.py` tracks multi-process resource usage
- **Distributed State**: `app/distributed_shared_state.py` handles cross-instance coordination

## Testing & Performance
- **Test Organization**: `tests/` contains functional, performance, unit, and interaction tests with Edge browser automation scripts
- **SQL Parsing Tests**: Recent focus on [tests/test_sql_caching_fix.py](tests/test_sql_caching_fix.py) for AST-returning function optimizations
- **Performance Profiling**: Built-in profiler outputs (`.prof` files) and SQL query compilation cache ([app/sql_compile_cache.py](app/sql_compile_cache.py))
- **Test Execution**: Use `python -m pytest tests/test_*.py -v` for specific test files 
- **Concurrent Protection**: [app/concurrent_protection.py](app/concurrent_protection.py) manages resource locks across multiple instances

## Project-Specific Conventions
- **Configuration Precedence**: Environment variables → production overrides → .env files → system registry
- **Module Naming**: `*_integration.py` for cross-system bridges, `prueba_*.py` for ad-hoc tests, `zzz_*` for external program loading
- **Database Patterns**: Dynamic database creation via `config_dict` mapping, separate configs for Development/Production/Test
- **Background Tasks**: Uses `app/background.py` with executor patterns, notification dispatching via Redis pub/sub

## Critical File Locations
- **Entry Points**: [flask_dashboards.py](flask_dashboards.py), [flask_dashboards_SSO.py](flask_dashboards_SSO.py)
- **Configuration**: [config.py](config.py), [apirobot_external_integration.py](apirobot_external_integration.py) 
- **App Core**: [app/__init__.py](app/__init__.py) (36K+ lines - main application factory)
- **Database Scripts**: `create_databases_*.bat` files for environment-specific database setup

                        args=None, 
                        kwargs=None, 
                        console_or_thread='thread', 
                        wait_for_thread=False,

    """
    execute_in_parallel
    Ejecuta la función especificada dentro de un módulo dado, ya sea abriendo una consola de Windows o
    mediante la creación de un hilo en el proceso actual. Para Windows se cierrra la consola al finalizar.
    Para el hilo se puede indicar si se espera a que finalice, y opcionalmente, pasar un callback
    que reciba el resultado de la función.

    Params:
        module_name (str): Nombre del módulo donde reside la función a ejecutar.
        function_name (str): Nombre de la función a ejecutar dentro del módulo.
        args (list): Lista de parámetros posicionales para la función.
        kwargs (dict): Diccionario de parámetros con nombre para la función.
        console_or_thread (str): "console" para ejecutar en una consola de Windows (no retorna resultado),
                                 "thread" para ejecutar como hilo.
        wait_for_thread (bool): True para esperar a que el hilo termine y retornar su resultado.
                                False para no bloquear la ejecución principal (retornará None).
        callback (callable): Función que se llamará (en el hilo) con el resultado de la función
                             cuando termine. Se ignora si no se provee.

    Ejemplo de uso:
    >>> from nombre_de_tu_archivo import execute_in_parallel

    >>> execute_in_parallel("mi_modulo", "mi_funcion", args=[1, 2], kwargs={"key": "value"}, console_or_thread="console")

    >>> # Ejecución en hilo, sin bloquear la ejecución (no esperamos resultado, usamos callback):
    >>> def mi_callback(resultado):
    ...     print("El hilo terminó, resultado =", resultado)
    ...
    >>> execute_in_parallel("mi_modulo", "mi_funcion", args=[1, 2],
    ...                     kwargs={"key": "value"},
    ...                     console_or_thread="thread",
    ...                     wait_for_thread=False,
    ...                     callback=mi_callback)

    >>> # Ejecución en hilo, esperando la finalización y obteniendo su resultado directamente:
    >>> result = execute_in_parallel("mi_modulo", "mi_funcion", args=[1, 2],
    ...                              kwargs={"key": "value"},
    ...                              console_or_thread="thread",
    ...                              wait_for_thread=True)
    >>> print("Resultado hilo:", result)
